## 4. Скорость и вес (Playwright, Pixel 7)

| Страница | Медленный 4G + CPU ×4: FCP / LCP | Без ограничений: FCP / LCP | Запросов | Передано |
|---|---|---|---|---|
| `/` | 3,7 с / 5,4 с | 0,8 с / 1,5 с | 30 | 685 КБ |
| `/doska` | 1,4 с / 1,4 с | 0,7 с / 0,7 с | 23 | 634 КБ |
| `/pilomaterialy` | 1,5 с / 1,5 с | 0,9 с / 0,9 с | 29 | 998 КБ |

CLS = 0 везде. Серверная обработка ≈0,1 с (TTFB 0,5 с с TLS). Из чего складывается вес
и что с этим делать:

- **JS 342 КБ на каждой странице, без сжатия.** nginx сжимает только `text/html`; в
  `deploy/nginx-piloproject.conf` gzip-директив нет, дефолт Ubuntu жмёт только HTML. Главный
  чанк `_nuxt/_AxUwnoq.js` 255 872 байт, в gzip 86 789. CSS почти весь инлайн в HTML
  (49–72 КБ на страницу) и жмётся вместе с ним; внешних CSS-файлов два по 0,6–2,6 КБ.
- **~53 КБ из главного чанка — тексты посадочных и прайса.** `definePageMeta.validate` в
  `pages/[landing].vue` импортирует `getSeoLanding`, и `seo-landings.ts` с
  `product-sizes.ts` уходят в общий бандл всех страниц. Проверять слаг по списку из
  `seo-routes.ts` — минус ~50 КБ на каждой странице.
- **`_payload.json` → 404 на каждой странице.** В head стоит
  `<link rel="preload" as="fetch" href="/…/_payload.json?_b=…">`, файла на проде нет:
  лишний запрос, 51 КБ тела 404 и ошибка в консоли. `useAsyncData` на сайте не используется,
  `experimental.payloadExtraction: false` убирает это без побочных эффектов.
- **HTTP/1.1** (`listen 443 ssl;` без `http2`): 10+ `modulepreload` и картинки идут
  очередями по 6 соединений.
- Картинки: каталог на мобильном грузит 6 картинок на 570 КБ (по 95 КБ). Кандидаты srcset
  уже ограничены 640w; тяжесть от портретного кропа 3:4 (`width="900" height="1200"`)
  для блока, который показывается ландшафтно. Ландшафтные `width/height` в `lumber.vue`
  и `[landing].vue` уменьшат вес примерно вдвое.
- Видео 5,8 МБ с `preload="none"` и постером 39 КБ не грузится до клика — нормально.
  У hero есть CSS-фон `bg-wood-forest.webp` 41 КБ, он может быть кандидатом LCP (без
  браузера не подтверждено).
- Заголовки: у `/images/*`, `/mp4/*`, favicon нет Cache-Control; у `/_nuxt/` и `/_ipx/`
  Cache-Control продублирован (`expires` + `add_header`); HTML без `Vary: Accept-Encoding`
  и charset; `.vtt` и `style.xsl` как `application/octet-stream`; security-заголовки не
  отдаются на `/_nuxt/` и `/_ipx/` (свои `add_header` в location перекрывают серверные,
  известно по `docs/security.md`), туда же не попадёт и HSTS, если не продублировать.
